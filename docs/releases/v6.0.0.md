# Ture v6.0.0

<!-- kap-minimum-macos: 26.0 -->

Tag: `v6.0.0`

Kap is now **Ture**, and Ture 6.0.0 records with ScreenCaptureKit, Apple's current screen capture API. It needs macOS 26 or later.

## The new name

This fork has moved far enough from Kap to take its own name. Kap + Ture = Kapture, the name Kap gives every recording, and your recordings keep that name. Your settings, plugins, shortcuts and recording history carry over: Ture reads them from the same place Kap did. Screen Recording and Microphone permissions carry over too, because the app ID stays the same.

## Requirements

- An Apple Silicon Mac (M1 or newer). There is no Intel build; Intel Macs can keep using [Kap 5.1.0](https://github.com/jacobpowaza/NewKap/releases/tag/v5.1.0).
- macOS 26 or later. On macOS 13 to 15, keep using [Kap 5.2.3](https://github.com/nikosalonen/Ture/releases/tag/v5.2.3). It doesn't offer this update on those versions.

## Install

1. Quit Kap, and move `Kap.app` from Applications to the Trash. Ture is the same app under a new name, and two copies confuse macOS permissions.
2. Download `Ture-6.0.0-mac-arm64.dmg`, open it, and drag `Ture.app` into Applications.
3. Open Ture. This release is signed with the fork's own certificate and is not notarized by Apple, so macOS refuses to open it the first time. Close the message, open **System Settings -> Privacy & Security**, and click **Open Anyway** next to the message about Ture.
4. Coming from Kap 5.2.x, Screen Recording and Microphone permissions should carry over, because these releases use the same certificate. Coming from another Kap build, macOS asks once more.

## Updating from Kap 5.2.x

On macOS 26 or later, Kap checks for updates every hour and offers this release, or right away when you choose **Check for Updates…**. **Update** downloads the DMG; install it as described above, including removing `Kap.app`.

## Changes

- **Recording.** Ture records with ScreenCaptureKit through its own recorder, `kap-recorder`, instead of aperture's AVFoundation recorder. A recording starts in about half a second.
- **Still screens.** A recording lasts as long as it ran, even when nothing on the screen changes.
- **Pause and resume.** Resuming is immediate, and microphone audio stays in sync with the video after a pause.
- **Quitting.** Ture quits on `kill` (SIGTERM) without waiting on the editor's "discard this recording?" dialog. It discards an active recording, as **Quit** does.
- **Crash recovery.** After a crash during a recording, Ture offers the recording at its next start again. Since 5.1.0 it did so only when it was opened with files.
- **Recording area.** On the first open after the app starts, the cropper on one display could ignore the mouse, so its dark overlay and toolbar showed but no area could be drawn.
- **Maximum quality.** ProRes recordings are saved as `.mov` files, which ProRes requires.

## For plugin authors

- `apertureOptions.cropArea.y` now counts from the top of the screen. Kap 5 and older counted it from the bottom.

## Known issues

- Not notarized: macOS asks you to approve each downloaded version once with **Open Anyway**.
- System audio capture still needs a loopback audio device. ScreenCaptureKit can record system audio, and Ture may use that in a later release.
